# 基于 MongoDB 的在线问卷系统——第一阶段项目报告

**完成日期：**2026-10-19  
**项目阶段：**第一阶段（初始需求设计、实现与测试）

## 1. 项目目标与完成情况

本项目依据《大作业一第一阶段.docx》的初始需求，实现可运行的在线问卷系统。注册用户可创建、编辑、发布和关闭问卷，并设置截止时间、生成分享链接；登录用户可填写问卷，系统支持匿名展示、按设置重复提交，以及单选、多选、文本、数字四类题型。题目支持必答和范围校验，以及由创建者配置的条件跳转。创建者可查看整份问卷及单题统计。

项目采用 **FastAPI + PyMongo + MongoDB**，前端使用原生 HTML/CSS/JavaScript。业务数据全部存储于 MongoDB，未采用关系数据库或现成问卷系统框架。已完成自动化测试与浏览器业务流程验收。

## 2. 系统设计

采用**模块化单体架构**：一个 FastAPI 应用中按业务划分模块，每个模块按需分离 API、Service、Repository，避免将业务规则写入路由或数据库操作函数。

| 模块 | 主要职责 |
|---|---|
| `accounts` | 注册、Argon2id 密码哈希、登录会话、身份认证 |
| `questionnaires` | 问卷与题目管理、发布前校验、状态及截止时间 |
| `responses` | 分享填写、答案校验、动态跳转、草稿、提交 |
| `statistics` | 汇总已提交答卷，提供问卷和单题统计 |

典型流程为：前端请求 → API 认证与参数校验 → Service 执行业务规则 → Repository 访问 MongoDB。发布后锁定题目与匿名/重复提交策略；创建者只能管理自己的问卷。答卷填写和统计均使用服务端校验，不能仅依赖前端限制。

## 3. MongoDB 数据库设计（重点）

### 3.1 集合与文档组织

| Collection | 核心数据 | 设计理由 |
|---|---|---|
| `users` | 用户名、规范化用户名、密码哈希、注册时间 | 独立管理账号；用户名唯一索引防止并发重名 |
| `surveys` | 创建者、标题、状态、截止时间、匿名/重复策略、`questions[]` | 题目及其选项、校验和跳转规则随完整问卷一同读取 |
| `responses` | 问卷和填写者 ID、状态、`steps[]`、`revision`、时间戳 | 答卷数量随填写人数增长，必须与问卷定义分开存储 |

题目嵌入 `surveys.questions`，因为题目隶属于一份问卷，展示与发布时通常整体读取；单文档修改也便于保持题目和跳转规则一致。答卷则**单独存储**，避免将不断增长的提交记录加入问卷文档。每份答卷将当前有效的回答步骤嵌入 `steps`，支持同一文档内原子更新和路径清理。

若改用关系数据库，题目、选项、跳转规则及步骤通常需拆入多张表；本项目更常按“整份问卷”“单份答卷”读取和更新，MongoDB 嵌入文档能减少关联查询，并适合当前的单文档原子操作。但 MongoDB 不提供这些引用的自动外键校验，题目 ID、选项 ID 和跳转目标有效性须由业务层保证。未来若允许发布后改题，需要考虑版本管理，而不能直接改写历史答卷所依据的题目定义。

### 3.2 关键索引与一致性

| 索引 | 用途 |
|---|---|
| `users.username_normalized` 唯一 | 防止重复注册；由数据库处理并发冲突 |
| `surveys(owner_id, updated_at)` | 查询当前用户创建的问卷 |
| `responses(survey_id, respondent_id, lifecycle_guard)` 部分唯一 | 每账号每问卷至多一份草稿，并在禁止重复填写时限制提交 |
| `responses(survey_id, status, submitted_at)` | 按问卷查询已提交答卷和统计数据 |

`lifecycle_guard` 的约定是：禁止重复填写时，草稿和已提交答卷均使用 `single`；允许重复填写时，草稿使用 `draft`，提交后移除该字段。因此唯一索引可防止重复草稿与并发重复提交。`responses.revision` 初始为 0，每次成功保存草稿或提交时递增；更新时比对预期版本，旧请求不能覆盖新结果。

索引负责可表达的唯一性约束；题型合法性、动态路径、发布状态、权限和截止时间仍由业务层校验。完整字段与索引定义见 [`mongodb-schema-v1.1.md`](mongodb-schema-v1.1.md)。

## 4. 条件跳转、填写与校验

**跳转设计。** 每道题保存可配置的 `jump_rules`（条件、优先级、目标题目 ID）。填写引擎按优先级匹配，首条命中即跳转；无匹配时进入下一题。单选按选项判断，多选支持 ANY/ALL，数字题支持比较运算。第一阶段只允许向后跳转，避免循环。例如 Q1 选 A 跳到 Q5 时，Q2—Q4 不属于当前答题路径，不能因其必答设置阻止提交。

**答案校验。** 全部在服务端执行：

| 题型 | 主要校验 |
|---|---|
| 单选 | 选项 ID 存在，必答题不可空缺 |
| 多选 | 选项有效且不重复，数量满足自定义最少/最多限制 |
| 文本 | 字符串类型、最短/最长长度 |
| 数字 | 数值上下界、是否必须为整数 |

**草稿与提交。** 每答完或主动跳过一题，保存一个 `answered` 或 `skipped` 步骤；只有非必答题可以主动跳过。修改前序答案时，后端重新计算有效路径并删除已失效的步骤，避免被绕过的答案进入统计。提交时再次校验完整路径、必答项和截止/关闭状态，成功后将 `draft` 转为 `submitted`。仅 `submitted` 中的 `answered` 步骤参与统计：单选统计人数、多选统计选项被选次数、文本列出回答、数字计算平均值。

## 5. 测试与验收

测试用例覆盖老师要求的六类情形。下表概括主要步骤、输入、预期与已记录的结果；逐项操作及更详细的输入输出见 [`test-cases-phase1.md`](test-cases-phase1.md)。

| 测试类别 | 操作与输入 | 预期输出 / 记录结果 |
|---|---|---|
| 创建问卷 | 登录后提交标题、说明、匿名设置 | 创建本人草稿问卷；通过 |
| 添加题目 | 在草稿中加入四种题型及限制配置 | 可保存题目并在发布前验证规则；通过 |
| 条件跳转 | 填写满足单选、多选或数值条件的答案 | 按规则到达目标题；修改前序答案后清理失效步骤；通过 |
| 答案校验 | 提交不满足文本长度、多选数量等限制的答案 | 服务端拒绝非法输入并提示；通过 |
| 提交问卷 | 另一登录账号完成答题并提交，尝试再次提交 | 成功保存已提交答卷；禁重设置下阻止重复提交；通过 |
| 统计结果 | 创建者读取已提交问卷及单题结果 | 选项次数、文本内容和数字平均值符合已提交答案；通过 |

最终记录为 **41 项 pytest 测试通过（7.20 秒）**。另在真实浏览器中验证了双账号完整流程、草稿刷新恢复、匿名界面、截止提示及 390×844 移动视口；跨源表单测试返回 403。全新 Python 虚拟环境安装、Uvicorn 启动、`/health` 与 API 文档访问也已验证。以上均为项目原有验收记录，本次报告修订未重新运行代码。

## 6. AI 使用情况与问题解决

使用 ChatGPT 辅助梳理需求和设计取舍，使用 **OpenAI Codex** 分阶段生成与修改后端、测试、前端和文档。需求中的匿名含义、重复填写策略、模块化架构、三集合模型、动态跳转优先级及 `steps`/`revision` 方案由开发者审查并确认；代码实现和后续修复主要由 Codex 执行，不能将其写成人工手写代码。具体提示词记录、生成内容与修改情况见 [`ai-usage-log.md`](ai-usage-log.md)。

| 实际发现的问题 | 处理方式与验证 |
|---|---|
| 切换题目类型后，编辑器错误读取旧表单 | 调整题型切换时的表单状态处理；浏览器复测通过 |
| 已发布问卷缺少截止时间设置入口 | 增加“问卷设置”操作；浏览器验证截止提示 |
| Cookie 认证的变更接口缺少显式来源检查 | 增加 Origin / Fetch Metadata 检查；跨源表单请求被拒绝（403） |

AI 的主要作用是加速实现与测试生成；其不足体现在界面逻辑和安全检查遗漏，必须通过真实浏览器与自动化回归发现、修正，而不能以 AI 已生成代码作为正确性证明。

## 7. 已知限制与结论

系统尚未对大量答卷统计进行压力测试；问卷关闭与并发提交分属不同文档，尚未使用跨文档事务保证严格先后顺序。当前非匿名问卷也未提供创建者查看填写者身份的专用接口，而原始需求未明确要求该接口。CSRF 防护依赖 Cookie 属性与来源校验，生产部署仍需 HTTPS 和 Secure Cookie。这些限制已记录，不影响已验证的第一阶段核心业务流程。

第一阶段已完成可运行的前后端、MongoDB Schema、条件跳转、统计和测试。项目保留原有代码及数据结构作为第二阶段增量扩展的基础，不提前推倒重做。部署配置见 [`../README.md`](../README.md)，接口见 [`api.md`](api.md)，完整数据库结构和测试用例分别见对应文档。
